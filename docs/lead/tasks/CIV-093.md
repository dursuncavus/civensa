# CIV-093 — UI screen map for the redesign

GOAL
The owner (designer, project manager of the UI redesign) will redesign every Civensa screen himself. He needs a complete screen map: one screenshot per screen plus, for each screen, what every visible element is and where each link/button goes. This task produces that map only; it changes no UI.

CURRENT STATE
- `scripts/guide_screenshots.py` (CIV-054) already starts the app on disposable PostgreSQL (`CIVENSA_TEST_POSTGRES_URL`), loads the book fixture, logs in with test accounts and takes Playwright screenshots into `docs/screenshots/guide-pp-v1/` with `INDEX.md`. ADAPT it; do not write a second harness.
- About 45 HTML GET routes in `app/` (excluding /api, json, export, download, static) and 45 templates.

WORK
1. Add a mode (e.g. `--ui-map --out docs/screenshots/ui-map-v1`) that visits every HTML GET page reachable by the strategy account and by one department (müdürlük) account, with realistic synthetic data so tables and forms are not empty. Include key states: empty list, filled list, form with a validation error, approved/frozen view, error page.
2. For each screenshot write an entry in `docs/screenshots/ui-map-v1/INDEX.md` (Turkish): screen name, URL pattern, which role sees it, purpose in one sentence, then a list of every visible link/button/form → its target URL or action and what it does. Generate the link list from the DOM (href/action/button text), then add the one-line meanings.
3. Add `docs/screenshots/ui-map-v1/navigation.md`: a Mermaid flowchart of screen → screen navigation, grouped by module (Performans Programı, Faaliyet Raporu, İç Kontrol, Yönetim).
4. List routes that could not be captured and why.

RULES
- Synthetic data only; no live database, no real person names beyond existing fixtures. The repo may become public (D-220).
- PNG ≤ 1.5 MB each (existing limit), desktop width 1440.
- Do not change app templates, routes or tests' behavior. Do not touch docs/lead/, AGENTS.md, workflows, or files of open PRs (#85, CIV-091, CIV-092). Never merge.

OUTPUT
One PR into feature/authorization-workflow-phase5 titled "CIV-093 arayüz ekran haritası".

ACCEPTANCE
- Every HTML GET route appears in INDEX.md as captured or explained.
- Each captured screen has its link/button table.
- Script runs from a clean checkout with one command (in INDEX.md); CI green on the final commit.
