CIV-090 — AR-06 deviation explanation before unit submission

GOAL
Close gap AR-06: a unit (birim) must complete the deviation explanation for every indicator whose verified actual differs from its target BEFORE the unit report can be submitted, and the indicator form must show clearly which fields are required for submission and what "saved as draft" means. Today the empty explanation is only caught at the very end, when Strateji approves (`approve_report`, app/activity_contract_service.py ~line 497).

CURRENT STATE
- Branch from `feature/authorization-workflow-phase5`.
- `save_actual` (app/activity_contract_service.py) stores value, state, evidence, explanation, deviation; `delta` = actual − single verified target, else None. Saving with an empty explanation is allowed (keep it allowed: draft saves must never be blocked by this rule).
- `approve_report` blocks with "Hedef ile gerçekleşme farkı için açıklama girin." when delta ≠ 0 and explanation is empty.
- Unit submission: `transition(..., action='submit')` in app/ar_unit_workflow_service.py builds the payload and calls `completeness(payload)`; it does not check deviation explanations.
- app/templates/activity_contract_detail.html shows explanation / corrective action fields without saying what is required.

RULES
1. "Needs explanation" = state == 'verified' and delta is not None and delta ≠ 0 and explanation.strip() == ''. Same rule as approve_report; put it in ONE helper used by both places (approve_report keeps its current message and behaviour).
2. Saving the actual stays allowed. After saving such a row, the indicator card shows a non-blocking warning: "Hedef ile gerçekleşme arasında {fark} fark var. Birim raporunu göndermeden önce açıklama girin." ({fark} in Turkish number format, the existing trnum filter).
3. The form marks the explanation field "Gönderim için zorunlu (fark varsa)" and shows one short line under the save button: "Kaydet taslak olarak saklar; eksik alanlar birim raporu gönderilirken kontrol edilir."
4. Unit submit (`transition` action 'submit') is refused with 409 when any indicator of that unit in the report's current revision needs an explanation. Message lists each indicator: "Birim faaliyet raporu gönderilemedi. Şu göstergelerde hedef farkı açıklaması eksik: {gösterge adı}; {gösterge adı}." with links (indicator anchors) on the HTML page, same pattern as existing blockers. Put the check in a new module app/ar_deviation_gate.py called from transition; read the indicators from the same data transition already loads, do not add another payload build.
5. Corrective action (düzeltici işlem) stays optional; do not make it required.
6. needs_review / missing states are not covered by this rule (other gates handle them); do not change those gates.

CONSTRAINTS
- No migration, no new dependencies.
- Do not change: app/main.py, app/activity_contract_routes.py, app/activity_contract_errors.py, app/activity_evidence_service.py, app/activity_financial_*.py, app/activity_sections_*.py, app/templates/activity_sections_*.html, app/templates/activity_contract_error.html, app/ar_typeset_*.py, docs/reports/civ-062-ar-gap-status.md, docs/lead/, AGENTS.md (D-137: PR #85 and task CIV-088 are open on these). If the rule cannot be done without one of them, stop and explain in the PR instead of editing it.
- Expected files: app/activity_contract_service.py (helper only), app/ar_unit_workflow_service.py (one call), new app/ar_deviation_gate.py, app/templates/activity_contract_detail.html, new tests/test_ar_deviation_gate.py.
