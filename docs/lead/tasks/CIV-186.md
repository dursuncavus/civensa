CIV-186 Sunum: tablo ve karne sayfalaması uzun adlarda alt bilgiye taşıyor

Follow AGENTS.md. Base branch: feature/authorization-workflow-phase5. Never merge, never deploy, never connect to the live database.

GOAL
Table slides (and scorecard slides) must never overlap the footer or run off the 1920×1080 slide, whatever the row text length. Today pagination counts rows only.

CURRENT STATE (DOĞRULANDI by the lead, 6 Nov, D-429)
1. app/sunum/engine.py prepare_slides: table → pages(rows, 10); scorecard → pages(rows, 6); bullets → pages(…, 5).
2. Reproduced with real 2025 data (İdare deck, "Müdürlüklere göre gösterge özeti", 33 müdürlük): names such as "Afet İşleri ve Risk Değerlendirme Müdürlüğü" wrap to two lines in the first column, so a 10-row page grows past the footer — rows 10–11 sit on/below the "Kaynak / Doğrulama kodu" line (screenshots in the D-429 PR description). Scorecard pages of 6 rows fit in the same deck; bullets/quote with long items not checked.
3. Lead workaround in the test deck only: rows split into pages of 7 before render. Not in app code.

PRIOR ART
Internal: engine pages(), numeric_columns() (alignment shared across continuation pages), "Tablo n/N" counters, #pdf mode. External: reveal.js has no automatic overflow pagination; print/report engines paginate by measured height (e.g. WeasyPrint/CSS fragmentation) — here a deterministic budget in Python is enough (no browser measuring, no new dependency).

RULES
1. Pagination stays in Python (engine rule "never Jinja"). Replace the fixed row count for 'table' with a line budget: estimate each row's line count from its longest cell (characters per line per column from the template's column widths at 1920×1080, Fira Sans, current font size; be conservative), and fill a page until the budget of the existing 10 single-line rows is reached. A single row taller than the budget gets its own page (never dropped, never truncated).
2. Same for 'scorecard' (name + subline per row) and 'bullets' (wrapped items), keeping the current maximums as upper limits.
3. Continuation pages keep the same headers, alignment and "Tablo n/N" numbering; slide order and ids otherwise unchanged.
4. Decks whose rows all fit on one line produce byte-identical output to today (tests must prove it with the existing fixtures).

CONSTRAINTS
