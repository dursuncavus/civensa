GOAL

Add the second recipe from D-411: "Faaliyet Raporu — İdare meclis sunumu", generated from the İdare report data with the same engine, look and outputs.

PRIOR ART
Internal: reuse the CIV-180 engine and the helpers in recipes.py (number, complete_sum, lines, rate, pages). Pattern: municipal council FR presentations summarise the institution first and compare directorates (budget share, staff, indicator achievement) instead of repeating every directorate's detail.

RULES
1. Recipe selection: İdare documents use the new recipe idare_activity_report(payload); birim documents keep activity_report unchanged (byte-identical decks for the existing birim tests).
2. Cover: organization name, year, subtitle "Meclis sunumu". Map + section separators + closing as in the müdürlük recipe.
3. Sections (skip any slide whose data is missing, log "Bu raporda … bilgisi yok" as CIV-180 RULE 4; never show zeros for missing data):
   a. "Kurumumuz": organisation duties/strategy text if present (bullets/quote as in the müdürlük recipe); total staff KPI + staff per müdürlük horizontal bar (sorted by value).
   b. "Bütçe": institution budget KPIs (kesinleşen ödenek, yıl sonu harcama, gerçekleşme oranı) only from complete data; spending per müdürlük horizontal bar if per-department amounts exist in the payload; else skip with a log line.
   c. "Göstergeler": per müdürlük indicator summary table (Müdürlük, gösterge sayısı, gerçekleşmesi girilen, ortalama oran %) computed only from verified values; no full indicator list. Table paging per engine (max 10 rows, "Tablo i/n").
   d. If the payload lists missing/unapproved units, one bullets slide "Henüz onaylanmamış birimler" with their names.
4. Every number from the payload; no hand-typed figures; Turkish number format via app/numbers.py; blank/null shown as "—".
5. Authorization unchanged: İdare deck only for users who may open the İdare report today.
