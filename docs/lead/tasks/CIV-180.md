CIV-180 Faaliyet Raporu sunumu (animasyonlu + PDF)

Follow AGENTS.md. Base branch: feature/authorization-workflow-phase5. Never merge, never deploy, never connect to the live database.

GOAL
Every müdürlük presents its Faaliyet Raporu to the mayor. Civensa must produce that presentation itself from the report data: one animated 16:9 presentation (single self-contained HTML file that opens in Chrome/Edge without internet) and the same deck as a static 16:9 PDF view. No numbers are typed by hand; every number comes from the report. This task builds the shared presentation engine and the first recipe: "Faaliyet Raporu — müdürlük sunumu".

CURRENT STATE (DOĞRULANDI by the lead on phase5, 4 Nov)
1. Visual reference, approved by the owner in review (D-411–D-415): docs/design/sunum/prototype.html (+ README.md, logo-beyaz.svg). Live preview https://claude.ai/artifact/DMpNp2f68JsogL2eMgJSRD. It uses reveal.js 6.0.1 (MIT) and Apache ECharts 6.1.0 (Apache-2.0) and Civensa's own tokens (app/static/design/tokens.css, Fira Sans in app/static/design/fonts). Its data are hard-coded; your job is to generate the same kind of deck from report data.

Existing exports: export.docx (app/ar_export.py), export.pdf (app/ar_pdf_export.py), export.json. Authorization: export_document() — own department only, Strategy all.
3. Number display helpers: app/numbers.py (Turkish 12.500 / 12.500,23).

PRIOR ART
Research done by the lead (D-413, sources in DECISIONS.md): reveal.js chosen over Slidev (Node build per deck), Quarto (server binary), Marp (little animation), Prezi/Gamma (commercial, manual numbers). Charts: ECharts (animated bars, valueAnimation count-up). Pattern taken: server-rendered HTML deck (Jinja) + reveal.js print view for PDF; "Prezi feel" = overview map slide whose tiles auto-animate into section slides. Internal: reuse export_payload/authorization and app/numbers.py.

RULES
1. Engine is generic: a Jinja macro per slide type — cover, map, section separator, KPI (2–8 figures, count-up), chart (bar / horizontal bar / stacked horizontal bar via ECharts), table, bullets, quote, closing. A recipe is a Python function payload → list of slide dicts; templates never compute numbers.
2. Look and motion exactly as the prototype: tokens, Fira Sans, logo top-left on cover, separators and closing; footer on every content slide = "Kaynak: <report + section>" left, "Doğrulama kodu <code>" right; icon buttons bottom right (map, notes, PDF) that auto-hide after 2.5 s; table rows appear automatically in sequence, total ≤ 1.5 s whatever the row count; bullets one per click; section tiles turn light green when their section was viewed; transitions ≤ 1 s.
3. Tables: max 10 rows per slide; longer tables continue on the next slide with "Tablo i/n"; font never shrinks. Bullets: max 5 per slide, rest continues.
4. Data: blank/null is shown as "—", never 0. Turkish number format from app/numbers.py. A KPI or chart is skipped (not shown with zeros) when its source data is missing; a short "Bu raporda … bilgisi yok" note goes into the generation log, not onto a slide.
5. Verification code: frozen/approved report → first 8 hex chars of sha256 over the canonical export.json payload, shown as "XXXX-XXXX"; draft → "TASLAK" badge instead of a code. Also show the same code on the FR report page so anyone can compare.
6. Two outputs from the same render: (a) GET /activity-sections/reports/{id}/sunum → opens the deck in the browser (same auth as export.pdf); (b) GET /activity-sections/reports/{id}/sunum.html → download, single self-contained file: reveal.js, reveal.css, echarts, fonts (woff2 base64) and logo (SVG base64) inlined, no http(s) reference left. PDF: the deck's "#pdf" view (reveal print view, @page 1920×1080, notes/buttons hidden, all numbers final, charts drawn without animation, all rows/bullets visible); the PDF icon opens it and the page tells the user to use Yazdır → PDF olarak kaydet. No Chromium or other new binary on the server.
7. Vendor files: put reveal.js 6.0.1 (dist reveal.js, reveal.css, reset.css) and echarts 6.1.0 (dist/echarts.min.js) under app/static/vendor/ with their LICENSE files; pin versions in a README there.
8. Logo: app/static/brand/logo-beyaz.svg (copy of docs/design/sunum/logo-beyaz.svg). Institution-level upload is a later task.
9. Recipe "FR müdürlük sunumu" v1 (use whatever the payload has; skip slides without data): cover (department, year, "Başkanlık sunumu"); map from the sections that produced slides; section "Müdürlüğümüz": duties (first ≤5 bullet lines of the yetki/görev section text), personnel KPI + employment chart, buildings table, strategic goal/target quote if present; section "Bütçe": budget KPIs (ödenek, harcama, gerçekleşme oranı computed) + chart; section "Faaliyetler ve göstergeler": activity table (name, cost, status if present) and indicator table (gösterge, hedef, gerçekleşen, oran); closing with the code. Strategy may open any department's deck.
10. Link it: on the FR report page next to the existing Word/PDF export links add "Sunumu aç" and "Sunumu indir" (Turkish labels exactly).
11. User-facing errors in Turkish: what happened, which report, what to do.
