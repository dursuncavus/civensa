# CIV-091 — Cut CI cost

GOAL
Halve GitHub Actions minutes for "Performance program validation" without losing coverage. October: 237 runs, each push ≈ 2 shards × ~40 min pytest (≈80 billed job-minutes). Account hit its Actions budget on 24 Oct (D-218).

CURRENT STATE
`.github/workflows/performance-program.yml`: pull_request (paths-ignore docs/md), concurrency cancel-in-progress already on, 2 shards, `pytest -n 4 --dist loadfile`, Postgres 18 service, Playwright chromium install. pytest step is 37–43 min per shard; setup is ~1 min.

RULES
- Do not delete, skip or weaken any test assertion. Coverage must stay the same test set.
- Do not touch docs/lead/ or AGENTS.md. Never merge.
- Turkish user-facing strings stay Turkish.

WORK
1. Skip test jobs on draft PRs: trigger types opened, synchronize, reopened, ready_for_review; job `if: github.event.pull_request.draft == false` (workflow_dispatch still runs). Keep the `secrets` workflow as is.
2. Profile: from `--durations` output and a local run, list the 25 slowest tests and the time spent in per-test DB setup/teardown and Playwright browser startup.
3. Fix the biggest cause(s) with the smallest safe change, for example: session- or module-scoped fixtures where tests do not share state, schema created once per worker (transaction rollback per test), one browser per worker instead of per test, removing real sleeps/timeouts. Check runner CPU count (already reported) and set `-n` to match.
4. Report before/after pytest minutes per shard in the PR description.

FORBIDDEN FILES
Anything changed by open PRs #85, #89, #90 (D-137), except shared conftest fixtures if unavoidable — then say so in the PR.

OUTPUT
One PR into feature/authorization-workflow-phase5, title "CIV-091 CI maliyetini düşür".

ACCEPTANCE
- CI green on the final commit, same number of tests collected as phase5 (state both counts).
- pytest step ≤ 20 min per shard, or a measured explanation of why not.
- Draft PR pushes start no test job (show one example run).
