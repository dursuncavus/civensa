CIV-185 Meclis sunumu: spot ve öne çıkan iş slaytları (rakamlar onaylı rapordan)

Follow AGENTS.md. Base branch: feature/authorization-workflow-phase5 (includes CIV-184). Never merge, never deploy, never connect to the live database.

GOAL
Strateji chooses the year's 3–5 key messages ("spot") and one "öne çıkan iş" per müdürlük for the İdare council deck. Strateji writes only the words; every number on these slides is picked from a list of facts computed from the report data and is resolved again from the exact approved payload when the deck is rendered. Look and behaviour exactly as the lead's design reference.

RULES
1. One fact catalogue module app/sunum/facts.py: facts(payload, unit_sources) → list of {key, label, department_id|None, value: Decimal, unit, display (Turkish format), source (report section)}. Keys are stable strings: org:staff_total, org:budget_final, org:budget_actual, org:budget_rate, unit:<dep>:staff, unit:<dep>:spending, ind:<dep>:<sha256(name)[:16]>:actual. Use exactly the same helpers and completeness rules as the existing İdare slides (incomplete → fact absent, never 0). Indicator facts only for actual_state 'verified'; two indicators with the same name in one unit → neither is offered. Money above 1 000 000 shown in milyon TL like the budget KPI. Test: catalogue values equal the values on the existing KPI/chart slides for the same payload.
2. Model (one Alembic migration, child of CIV-184's head): table sunum_highlights — id, organization_id, period_id, year, kind ('spot' | 'feature'), department_id (nullable for org facts; required for feature), fact_key, label (≤ 40, optional text under the number; default = fact unit), sentence (required, ≤ 180), context (optional, ≤ 80), photo_id (feature only, optional, FK sunum_photos ON DELETE SET NULL, must be a 'single' photo of the same department and year), selected, sort_order, created_by, created_at, updated_at. Limits: at most 5 selected spots; at most one feature per müdürlük per year. Downgrade refuses when rows exist (same pattern as CIV-184).
3. The sentence and label must not contain digits (Turkish error: "Cümleye rakam yazmayın; rakam rapordan otomatik gelir. Rakamı listeden seçin."). Context may contain digits (place names).
4. Screen (Strateji only, same permission pattern as CIV-184, UPLOAD_ROLES-style one-line widening for later): page "Meclis sunumu öne çıkanlar" for the İdare report, linked next to the photo page. Two sections: Spotlar (n / 5) and Öne çıkan işler (one card per müdürlük). Form: fact picker (grouped by Kurum / müdürlük, shows label + current value), label, sentence, context, photo picker (thumbnails of that müdürlük's single photos), "Sunumda göster", up/down order, edit, delete with confirmation. Values on this screen come from the current report data and are labelled "Güncel rapor verisi"; if a fact disappears, the row shows "Bu rakam raporda artık yok; başka bir rakam seçin." Reuse Civensa layout and the CIV-184 page styles.
5. Deck: new slide types 'spot' and 'feature' in the engine + templates. İdare recipe adds group "Yılın öne çıkanları" right after the cover/map with the selected spots in order (alternate green/dark background, eyebrow "Yılın öne çıkanları · n / N"); feature cards (3 per slide, in sort_order) open the "Tamamlanan işler" group before the photos. Number resolved at render from the deck's own payload + pinned unit sources via facts(); missing fact → that spot/card skipped + log line (never a stale number, never a typed number). Card without a photo → card without image area (no placeholder). Counting animation as the prototype; #pdf and prefers-reduced-motion show the final value. Footer source = the fact's report section; feature slides "Müdürlük bölümleri". Highlights are not part of the approved report payload and do not change the verification code.
6. Birim decks stay byte-identical when no highlights exist; İdare deck stays ≤ 8 MB with 5 spots + 12 cards + 16 photos.
