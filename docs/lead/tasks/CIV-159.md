CIV-159 Health hazırlık alanı

Follow AGENTS.md. Base branch: feature/authorization-workflow-phase5. Never merge, never deploy, never connect to the live database.

GOAL
Make `/health` say whether the app is ready to serve: database reachable AND its Alembic revision equals the code's head. Then turn the strict-xfail readiness check in tests/test_release_upgrade_from_live.py into a normal passing assertion. D-318 follow-up.

CURRENT STATE
- `app/main.py` `health()` (GET /health) runs `SELECT 1` and returns `status` "ok"/"degraded", app, version, environment, database {backend, status, latency_ms}; 503 when the database fails.
- `migration_head()` in app/main.py already reads the script head from migrations/ (lru_cache). Production startup runs `alembic upgrade head` in `lifespan` before traffic.
- tests/test_release_upgrade_from_live.py: `test_populated_live_schema_upgrades_twice_and_serves_app` is `xfail(strict=True, raises=HealthReadinessMismatch)` because /health lacks `status == "ready"` and `migration == head`. That expectation was written by the lead without reading the route (D-318). The contract below replaces it.
- Render civensa-pilot uses /health as its health check (BELİRSİZ which path/fields; verify in repo docs or render config if present and report).

PRIOR ART
Standard readiness/liveness split (Kubernetes-style probes; e.g. alembic `MigrationContext.get_current_revision()` for the DB revision). Reuse `migration_head()` and the existing engine; no new endpoint framework, no new dependency.

CONTRACT (exact)
Keep every existing field and its meaning (`status` stays "ok"/"degraded" so existing monitors do not change). Add:
- `ready`: true only when database status is ok AND current revision == code head.
- `migration`: {"current": <revision or null>, "head": <code head>}. If `alembic_version` is missing or unreadable, current = null and ready = false.
HTTP: 200 when ready; 503 when the database fails (as today) or when ready is false; `status` becomes "degraded" in both 503 cases. The revision read must be one cheap query on the same connection as `SELECT 1`; no table scans, no writes. Never include connection strings, hostnames, user names or exception text in the body.

WORK
1. Implement the contract in `health()`.
2. tests/test_release_upgrade_from_live.py: remove the xfail and `HealthReadinessMismatch`; assert `ready is True` and `migration == {"current": head, "head": head}` after the double upgrade. Name this changed test and why in the PR (D-167).
3. New focused tests: ready on a migrated disposable PostgreSQL; ready false + 503 when the database is one revision behind (downgrade a disposable DB by one step, or stamp an older revision); 503 + no secret text when the database is unreachable; body has no URL/host/user.
4. Search the repo for anything that parses /health (tests, ops scripts, workflows, docs/operations, runbooks) and keep it working; update operational docs that describe the /health body in one line each.
