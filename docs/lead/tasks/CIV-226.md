# CIV-226 — pages that list every directorate: read shared rows once

Owner: lead (CV Lider 76). Review: Codex (GPT-6.1 Sol, high), clean on 655e8c9. Decision: D-489.

## Problem (DOĞRULANDI, live 15 Nov before the fix, 3 loads each)
- Genel Bakış `/dashboard` 6.2–7.1 s, `/api/progress` 5.4–6.0 s, Rapor Oluşturucu `/report-builder` 6.2–11.2 s, Faaliyet Raporu `/activity-report` 2.2–3.5 s, Kurum Yapısı `/structure` 2.1–2.4 s, Kullanıcılar `/users` 1.0–2.3 s.
- Same cause as CIV-224/225 ([[civensa-live-latency]]): hundreds of queries × ~6–10 ms Neon round trip.
- Local survey (33-directorate fixture): dashboard 458, department dashboard 463, `/api/progress` 444, activity report 410, structure 353, users 214, report builder 1927 queries.

## Change
- `program_service.validate_departments`: validation for all directorates with one query per table; the progress overview called `validate_department` per directorate.
- Department dashboard computes only its own progress row.
- `structure_service.request_read_scope` on the six GET routes: directorate display names read once per request (cache cleared on structure writes/flush).
- `unresolved_work`: persistent indicator ids in one query, only for closed directorates.
- Report builder: catalogue responsibilities and link checks in bulk; `_serialize_department_state` links in one query.

## Result
- Fixture: dashboard 458 → 32, department dashboard 463 → 35, `/api/progress` 444 → 24, activity report 410 → 9, structure 353 → 22, users 214 → 7, report builder 1927 → 443.
- Live: see D-489.
