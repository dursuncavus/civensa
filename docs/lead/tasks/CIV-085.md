CIV-085 İç Kontrol soru formu

Follow AGENTS.md. Base branch: feature/authorization-workflow-phase5. Never merge, never deploy, never connect to the live database.

GOAL
Add the İç Kontrol İzleme Soru Formu (gap G5 from CIV-082) to the CIV-079 six-month monitoring module: Strateji uploads a question list, attaches it to a monitoring period, every participating directorate (harcama birimi) answers each question Evet / Hayır / Geliştirilmekte for itself, Strateji returns or approves, and the system computes the answer percentages. Narrative sections (misyon/vizyon, bileşen değerlendirmeleri, güçlü yönler, gelişim alanları, öneriler, puan aralığı = G6) are NOT in this task; they follow as CIV-160.

WORK
1. Question list (Strateji only). New "Soru formu" upload on the İç Kontrol screens: downloadable Excel template with columns Sıra | Bileşen | Kod | Soru. Bileşen must be one of the five components as already named in the plan catalogue (accept the codes KOS/RDS/KFS/BİS/İS and the catalogue names). Validate: no empty Soru, unique Kod, unique Sıra, max 200 rows, known Bileşen; row-numbered Turkish errors; nothing saved when any error. A saved list is an immutable version (name + upload time + uploader). Show the parsed list for review before saving.
2. Attach to a period. Strateji Müdürü attaches one saved question list to an OPEN monitoring period and selects participating directorates (default: all active departments; checkbox list). This creates one questionnaire batch per selected department. Attaching is allowed only while no answer has been saved in that period; afterwards the list and participants are fixed (a department can be added later; none removed once it has answers). One question list per period.
3. Directorate answers. On "İç Kontrol Eylemlerimiz" (our-actions), a new block "Soru formu" for the selected period: one row per question (Kod, Soru, three radio options, optional Açıklama up to 1000 characters). Save keeps partial answers; Submit requires every question answered (Turkish message naming the missing codes; form values kept). Same roles, deadline rule, revision check and Turkish messages as the action entries. Directorates see only their own form.
4. Strateji review. Overview lists each participating directorate's questionnaire status (Taslak / Gönderildi / İade edildi / Onaylandı, answered x/total). Detail shows answers read-only with Return (reason required) / Approve / Reopen (reason required), following the CIV-079 rules and the same separation of duties.
5. Results (computed, never typed). From current approved questionnaires only: per question and per component the count and percentage of Evet / Hayır / Geliştirilmekte, and the institution total. Show "n/N" next to every percentage; Turkish number format with comma and 2 decimals via the existing formatter; denominator 0 → "— (0/0)". Also per directorate and for the institution (D-336, practice in the 2020-2022 two-year report, verified on 12 directorates): Toplam puan = 2 × Evet + 1 × Geliştirilmekte + 0 × Hayır (maximum 2 × question count), and Gerçekleşme oranı = (Evet + Geliştirilmekte) / question count; document both in izleme.md as "2022 uygulaması — Strateji teyit edecek". Show how many directorates are included and list those not yet approved. Do not derive "güçlü yön / gelişim alanı" labels — that is narrative (CIV-160).
6. Export. Add a "Soru formu sonuçları" Excel download (sheet 1: per-component summary; sheet 2: per-question summary; sheet 3: per-directorate answers). Draft rule identical to the existing exports (TASLAK unless every participating questionnaire is approved). Existing exports, including the CIV-084 official Word/Excel, stay byte-for-byte unchanged.
7. History and immutability. Question list versions, questionnaire answers and decisions are append-only like ic_monitoring_entries/events (reuse reject_history_change). Annual Excel is unchanged.
8. Migration: exactly one new migration on top of c086a1b2c3d4. Downgrade must not discard data: refuse with a Turkish message when any questionnaire data exists, drop the new tables only when empty.
9. Docs: add a "Soru formu (CIV-085)" section to docs/internal-control/izleme.md (Turkish): upload, attach, answer, review, the result formula, and the assumption "katılımcı birimleri Strateji seçer — varsayım, Strateji teyit edecek".
10. Screens: check 1366 px and 390 px for the upload, attach, directorate form, overview and detail states (empty, partial, submitted, returned, approved, error); screenshots under tests/artifacts/civ085/ with a short count summary (D-252).
