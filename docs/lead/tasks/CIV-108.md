# CIV-108 — 022 department home as a task list: static prototype

GOAL
The department home (/dashboard, role department, screen 022) shows three number cards and one "Çalışmaya devam et" panel; most of the page is empty and it does not say what is left to do. Prototype a task-list home (owner approves the look before any app code changes; D-243: a new pattern gets a prototype first).

PRIOR ART (D-271)
CIV-107 research (Google Doc "CIV-107 Ekran araştırması", D-272 item 1): task-list pattern of the GOV.UK Design System, also used by the NHS, Ministry of Justice and HMRC design systems — an ordered list of steps, each a link with a text status on the right ("Tamamlandı", "Başlanmadı", "Devam ediyor"), status never by colour alone. Use that pattern's structure; style it with the Civensa design system (docs/design/prototype/tokens.css, prototype.css, D-224 principles).

CURRENT STATE
- feature/authorization-workflow-phase5 after CIV-106 (#148, 1ed8620): 022 at ≥ 1280 px = main column + right summary column (Gösterge, Civensa kontrolü, Gönderim); below 1280 the cards are a compact strip above.
- Data already in the 022 template context (app/main.py dashboard route, department branch): `indicators` (with `.values`), `issues` (number of indicators with Civensa issues), `submission.status` (draft / submitted / returned / approved, shown via the `status_label` filter), `department`, `period`.
- Static prototype pattern: docs/design/prototype/ (tokens.css, prototype.css, screens/*.html, screenshots via the existing capture script).

WORK (prototype only)
1. New docs/design/prototype/screens/022-department-home.html, inside the same shell as the other prototype screens. Main column: a "Bu dönem yapılacaklar" panel with three ordered steps:
   1. "Veri girişi" → link "/department/{id}?period_id={id}". Status: "Başlanmadı" (no indicator has a value), "Devam ediyor" (some values), "Tamamlandı" (every indicator has its required values and 0 issues).
   2. "Civensa kontrolü" → same link. Status: "Düzeltme gerekli · N gösterge" when issues > 0, "Sorun yok" when 0 after data entry, "Bekliyor" before any entry.
   3. "Gönderim" → status from submission: draft "Gönderilmedi", submitted "Gönderildi", returned "İade edildi — düzeltip yeniden gönderin", approved "Onaylandı". Submit itself stays on the data-entry screen; this row only links there.
   One short help line under the heading (keep the current sentence "Gönderimden önce Civensa tüm göstergelerdeki zorunlu alanları ve temel tutarlılık kontrollerini çalıştırır."). Right summary column stays as built in CIV-106.
2. Status shown as text inside a status tag (design-system badge); colour only supports the text (neutral, warning for "Düzeltme gerekli"/"İade edildi", success for "Tamamlandı"/"Onaylandı"/"Sorun yok"). Contrast ≥ 4.5:1.
3. States to show (a state switcher in the prototype page, like prototype.js does elsewhere): (a) new period, nothing entered; (b) entry in progress with 3 issues; (c) everything entered, 0 issues, not sent; (d) submitted; (e) returned with issues.
4. 390 px: steps stack; the status tag goes under the step name; no horizontal scroll.
5. Sentence case, Turkish texts exactly as above; list every new text in the PR.
