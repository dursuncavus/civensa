# CIV-138 — Readable audit history and budget list (no raw codes or internal numbers)

Base branch: `feature/authorization-workflow-phase5`. Follow AGENTS.md. Never merge. Open the PR into `feature/authorization-workflow-phase5`.

GOAL
Owner feedback (27 Oct 16:49–16:51): Strategy users cannot read raw English codes and internal database numbers. On 016 /audit the İşlem, Varlık and Ayrıntı columns show values like `activity_update`, `activity #42`, `revision=3;subprogram_id=15` or JSON. On 017 /budget-reallocations the first column shows "#9202 · İncele" and the last shows "#9201 için telafi" — internal ids that appear on no official document.

PRIOR ART
Keep raw values for traceability and translate only at display (same pattern as `app/pp_display.py` `EVENT_LABELS` / `event_label`, `actor_label`). One central mapping, a safe fallback for unknown codes.

WORK
A. Audit history (016)
1. New module `app/audit_display.py`: `ACTION_LABELS` (Turkish past-tense phrase for every action code written anywhere in `app/` — find them all with grep over `log(db, …)` and `AuditLog(action=…)`, e.g. `activity_update` → "Faaliyet güncellendi", `user_create` → "Kullanıcı oluşturuldu", `login` → "Giriş yapıldı", `budget_reallocation` → "Bütçe aktarıldı"), `ENTITY_LABELS` (e.g. `activity` → "Faaliyet", `user` → "Kullanıcı", `import_batch` → "Veri aktarımı", `budget_operation` → "Bütçe aktarması"). Unknown code → "Diğer işlem" / "Diğer kayıt" and the raw code moves into the technical details (item 4). A unit test fails if any action/entity code used in `app/` has no label.
2. İşlem column and the İşlem filter dropdown show the Turkish label; the `<option value>` stays the raw code (filter and CSV links unchanged).
3. Varlık column: "Faaliyet: <name>" / "Kullanıcı: <full name>" / "Müdürlük: <name>" where the entity still exists (one batched lookup per entity type for the rows on the page — no per-row query); if the record no longer exists: the type label alone ("Faaliyet (silinmiş)"). No "#id" in the visible text.
4. Ayrıntı column: known `key=value;…` keys translated into a short Turkish sentence (revision → "Revizyon 3", role → role label, count → "12 kayıt", subprogram_id/department_id → name via the same batched lookup, period_id → period year, bytes → "1,2 MB"); JSON details summarised the same way where keys are known. Anything not translatable goes into a closed `<details><summary>Teknik ayrıntı</summary>` with the raw text. `safe_audit_details` masking stays first and unchanged.
5. CSV export: unchanged (raw codes) — it is the traceability record.
B. Budget reallocation list (017)
6. First column: link text = departments and amount from the operation lines, e.g. "Fen İşleri → Park ve Bahçeler · 5.000.000,00 TL" (decrease side → increase side, more than two departments: first one + "ve 2 müdürlük daha"); href unchanged. Load lines in one query in the list route.
7. Geri alma column: "Telafi: <Dayanak> <tarih> / <sayı>" of the reversed operation; href unchanged.
8. No "#id" in visible text on 017. 018 and the detail page out of scope (report them, item 9).
C. Report only
9. In docs/design/rollout/civ-138/README.md list every other user-facing template that shows raw codes, English enum values or "#id" (file + line + example). Do not change them — other open PRs are editing those screens.
