RULES
1. Allowed difference, nothing else: an activity whose load-time subprogram_id was NULL and that now has a subprogram set through a recorded mapping operation after its first_load_department audit (activity_mapping_csv apply, or another mapping route you identified in state 4 that writes an audit row naming the activity and the new subprogram). Its card_id may differ only as a consequence of that mapping.
2. Proof: for those activities substitute subprogram_id=None and the card_id the loader would have set (state 3), rebuild the hash, and require it to equal applied_hash exactly. If it does not match, return None as today. Activities that had a subprogram at load and were moved are a content change → still refused (this keeps 2027 book memberships protected).
3. The current subprogram of each mapped activity must belong to the same period; the latest mapping audit for that activity (after reverts) must name the current subprogram_id. A reverted batch leaves no allowed difference.
4. Every other check in approved_book_provenance stays as is.
5. The publication records it: add to the stored approved-book provenance/warnings block the count of mapped activities and the list of mapping batch ids (compact, no per-row texts). Turkish label for the UI/history if shown: "Onaydan sonra faaliyet eşleştirmesi: N faaliyet".
