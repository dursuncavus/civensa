# CIV-110 — İç Kontrol: no "İncelemeye gönder" button after the entry deadline

GOAL
After a monitoring period's entry deadline the department screen still shows "İncelemeye gönder" although entry is read-only; pressing it only returns the server error "İzleme gönderim süresi doldu…" (409). Hide the button after the deadline and show the reason instead. Server behaviour stays as it is.

PRIOR ART (D-271)
Bug fix on an existing screen; no new pattern. CIV-107 finding (D-272 item 3): read-only states must look clearly locked, not offer actions that fail.

CURRENT STATE
- feature/authorization-workflow-phase5 after CIV-105 (#150) and CIV-106 (#148).
- DOĞRULANDI: app/internal_control_monitoring_service.py `transition()` rejects submit when `today(db) > period.deadline` (409, message above). The entry form is already hidden after the deadline; only the submit form in the `entries` macro (app/templates/internal_control/monitoring_shared.html, line 29) is gated on `closed_at` and status, not on the deadline (found in the CIV-105 review, D-274).
- monitoring_shared.html is used by the department screen monitoring_ours.html AND the strategy screens monitoring.html and monitoring_detail.html. CIV-105 tests (tests/test_ic_our_actions_design.py) freeze the strategy screens' HTML byte for byte against fixtures in tests/fixtures/ic_our_actions_start/, and monitoring_ours.html replaces the macro's batch heading `<h2>{{ detail.batch.label }} · {{ states[detail.status] }}</h2>` by string match.

WORK
1. In the `entries` macro, render the submit form only when the period's entry deadline has not passed (use the same "today" source the server uses — if the template has no such value, pass a boolean from the route context; do not compute dates differently from `today(db)`). After the deadline, where the button was, show one line: "Gönderim süresi doldu (son giriş: DD.MM.YYYY). Süre uzatımı için Strateji birimiyle görüşün."
2. Do NOT change the batch heading markup on line 10 (CIV-105 depends on it).
3. Strategy screens: the strategy user's actions (approve, return, reopen) are unchanged. If the strategy screens' HTML changes only by the removed submit button / added line in the expired case, update the frozen fixtures in tests/fixtures/ic_our_actions_start/ deliberately and say exactly what changed in the PR; any other strategy HTML difference is a failure.

RULES
AGENTS.md applies. Never merge. No change to transition(), routes' permissions, database or other screens. Sentence case. Tokens only for any style. No uppercase text-transform.

CONSTRAINTS
Only app/templates/internal_control/monitoring_shared.html, the route that renders it if a boolean must be passed (app/internal_control_monitoring_routes.py, context only), tests (existing IC tests + fixtures), docs/design/rollout/civ-110/**.

TESTS

Strategy: approve/return/reopen forms unchanged in all states. Full suite green.
