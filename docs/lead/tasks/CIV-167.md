GOAL
İç Kontrol monitoring must print each directorate with the name it had in the monitoring period's year, as PP / Faaliyet Raporu already do via "Kurum yapısı" decisions (D-359 gap a). Real near-term case (BEYAN, owner): Afet İşleri Müdürlüğü becomes "Afet İşleri ve Risk Yönetimi Müdürlüğü" in 2027; the 2026 second-half monitoring report is produced in January 2027 and must still print the 2026 name.

CURRENT STATE (DOĞRULANDI by the lead on phase5 758522c)
1. app/structure_service.py period_name(db, period_id, department) gives the name for a ReportingPeriod: DepartmentScope.display_name if set, else the 'before' name of a live structure change whose effective_date.year is after the period year, else department.name. It takes a ReportingPeriod id; İç Kontrol periods are ICMonitoringPeriod (year, half), so it cannot be called directly.
2. app/internal_control_monitoring_service.py (~line 101–113, period open): ICMonitoringBatch.label = dep.name (current name at the moment of opening). A period opened after the rename's effective date gets the new name even for an earlier year.
3. app/internal_control_monitoring_export.py official_data() ~line 193: responsible and cooperating party names = db.get(Department, party.department_id).name (current name) — a re-export of an old period after a rename prints the new name.
4. Merge/split/close handling for İç Kontrol (D-359 gap b) is NOT part of this task.

- Already exported / frozen files are not regenerated. No migration expected; if one seems necessary, stop and explain in the PR.
- Unit-facing screens keep showing the unit's own current name in navigation; only period-bound İç Kontrol content changes.
