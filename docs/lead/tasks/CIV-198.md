PRIOR ART
SQLAlchemy `selectinload`/`joinedload` (already used elsewhere in app/; follow the existing style), a per-call dict cache passed as an argument, `db.add_all` / executemany via `db.execute(insert(Model), [rows])`. DECISIONS (lead)
1. Behaviour must not change. In particular `book_snapshot`, `department_snapshot`, `department_package_snapshot` and `cost_reconciliation` must return exactly the same data in the same order: these feed sha256-pinned publications. Keep dict key order and sort order.
2. Allowed techniques: eager loading; loading a period's rows once and grouping in Python; passing already-built snapshots into `cost_reconciliation` instead of rebuilding them; a request/call-scoped cache for `live_changes`/decoded `snapshot_json` (pass it in or keep it on the call stack; no module-level global cache, no cache that outlives a request, because structure changes must show immediately); bulk INSERT.
3. Not allowed: changing models, migrations, templates, routes' responses or URL; adding a dependency; caching across requests; skipping a validation or publication check to save queries.
4. Targets (measured with the CIV-196 script, same data): step1 ≤ 1400, step2 ≤ 2500, step3 ≤ 200, step4 ≤ 1200 statements. These are targets, not proven feasible. If one cannot be reached without breaking decision 1, stop at the safe gain and explain why in the report.
