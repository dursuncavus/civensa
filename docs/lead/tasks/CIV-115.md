# CIV-115 — CI: per-test timeout so a hanging test fails with its name

GOAL
Job "test (18, 1)" of workflow "Performance program validation" hung twice on 26 Oct 2026 (> 18 min while the other shard finishes in ~9 min; reruns pass in ~13 min). A hang gives no test name and costs 25–45 min. Make any hanging test fail fast with its name and a stack trace in the annotations, and find the likely hanging test.

PRIOR ART (D-271)
pytest-timeout (pytest-dev, standard plugin, works with pytest-xdist). Use it; do not write a custom watchdog.

CURRENT STATE
- .github/workflows/performance-program.yml: matrix shard 0/1, `timeout-minutes: 45`, pytest `-n <cpu> --dist loadfile --max-worker-restart=0 --ci-shard-index/count`, failure annotations via ops/ci/pytest_annotations.py.
- requirements-dev.txt: pypdf, playwright, pytest-xdist. pytest.ini: only testpaths. No per-test timeout anywhere.

WORK
1. Add pytest-timeout (pinned) to requirements-dev.txt only (dev/test dependency, not runtime — D-224 not affected).
2. Configure a per-test timeout of 300 s with the signal method in pytest.ini (signal raises inside the test, so the xdist worker survives and the failure is reported normally with --max-worker-restart=0; verify this and explain in the PR if you choose otherwise).
3. Make sure a timeout failure reaches the annotations (ops/ci/pytest_annotations.py) with the test id; add a test for that.
4. Lower the job `timeout-minutes` from 45 to 30.
5. Read shard 1's test files (as selected by --ci-shard-index=1) and list in the PR the tests most likely to hang (browser/Playwright waits without timeout, subprocess without timeout, DB locks across workers). Do not change those tests in this task; only list them with file:line and the reason.

RULES
- AGENTS.md applies. Never merge; never touch main/staging, docs/lead/** or AGENTS.md; no app code, database, migration or secrets change. Do not change test selection, sharding or xdist settings beyond the timeout.

CONSTRAINTS
Only: requirements-dev.txt, pytest.ini, .github/workflows/performance-program.yml (timeout-minutes line only), ops/ci/pytest_annotations.py (only if needed for step 3), tests/test_ci_* (new or existing CI tests).

TESTS
- A test proves a test exceeding a (small, test-local) timeout is reported as a failure with its node id and the annotation script emits it.
- Full suite green on CI; total duration of each shard not worse than before by more than 1 min (give before/after from the run).

OUTPUT
One PR into feature/authorization-workflow-phase5 titled "CIV-115 CI test zaman aşımı". Turkish description: what changed, why 300 s, list of likely hanging tests with reasons, shard durations before/after.
