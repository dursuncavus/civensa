# CIV-116 — 036/037 Rapor hazırlığı: static prototype

GOAL
The "Rapor Hazırlığı" screen (/program/{department_id}, screens 036 strategy, 037 department, 087/088 approved read-only in docs/screenshots/ui-map-v1/INDEX.md) is one very long page: seven sections, dozens of forms, Title Case headings, no overview of what still needs work. Department users fill it every period, so it is the next D-243 screen after the strategy review screens. It needs a new page pattern (section overview + navigation), so per D-243 it gets a static prototype first; the owner approves the look before any app code changes.

PRIOR ART (D-271)
- GOV.UK Design System "task list" (already used in CIV-108 for 022): each section is a row with a text status; status never by colour alone.
- GOV.UK "contents list" / sticky in-page navigation on long guidance pages: a short list of anchor links to the page's sections.
- Civensa's own 024 (department.html) uses tabs; tabs are NOT used here because the sections are one sequential workflow and errors must stay visible on one page (CIV-107 finding: do not hide unfinished work).
Use that structure, styled with the Civensa design system (docs/design/prototype/tokens.css, prototype.css, D-224 principles).
