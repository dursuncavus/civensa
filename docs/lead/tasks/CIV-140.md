# CIV-140 — Faaliyet raporu revizyonu (007/008): visual indicator summary

Base branch: `feature/authorization-workflow-phase5`. Follow AGENTS.md. Never merge. Open the PR into `feature/authorization-workflow-phase5`.

GOAL
Owner feedback (27 Oct 16:56, /activity-reports/revisions/{id}): each indicator section is a long column of text lines and is hard to read and follow. Make the state of each indicator readable at a glance, and the whole report trackable.

PRIOR ART
Bullet chart (Stephen Few): one bar for the actual value plus a thin marker for the target, no traffic-light colours. GOV.UK summary list for label/value pairs. Reuse the existing design-system tokens, badges and panels from CIV-135 (`activity-report-detail.css`) — no chart library.

HARD RULE (docs/performance-activity-contract.md lines 62, 79, 102)
No percentage achievement, no success direction, no green/red "good/bad" judgement on actual vs target. The bar is neutral (accent/secondary tokens). Only the existing numeric difference text is shown. If a target is missing, not verified, zero, or there is no numeric actual, draw no bar — show the existing text only.

WORK
1. Report summary at the top (under the revision panel): one line of label/count pairs grouped by data state, e.g. "4 gösterge · 2 Doğrulanmış · 1 İncelenmeli · 1 Kayıt yok · 1 açıklama bekliyor" (D-299: one-line summary; status = text + colour badge). Counts come from data already in the template context (`report.indicators`, `row.actuals[-1]`, `needs_deviation_explanation`) — no new service or query.
2. Per indicator, a summary block directly under the indicator name:
   - Left: actual value large ("80") with unit ("Adet"), the data-state badge next to it; right next to it (D-292: label next to value, nothing pushed to the far edge, block ≤ 44rem): "Hedef 100" and "Fark −20".
   - Under it the bullet bar: track = max(actual, target) × 1.1; filled bar = actual; thin vertical marker = target; aria-hidden="true" (the numbers above are the accessible text).
   - If `needs_deviation_explanation`: the existing deviation warning text stays, as a compact warning badge/panel inside this block.
3. Definition (department · unit · code, explanation, calculation, source): a compact label/value list (Birim, Kod, Müdürlük, Hesaplama, Kaynak, Açıklama) inside a `<details>` "Gösterge tanımı", closed by default.
4. Evidence of the latest actual: a compact list, one line per source (title · locator · version), file link under it; keep all texts.
5. Separate the entry form visually from the read-only part: a panel heading "Yeni gerçekleşme gir" above the existing form (the only new visible text besides the summary and "Gösterge tanımı").
6. History `<details>` unchanged in behaviour.

RULES
Every form element, attribute, hidden value, textarea content, link, id/data/aria hook and existing visible text stays (the CIV-135 frozen contract test must pass; extend its allow-list only for the new summary/bar/details markup and document every new visible text in the README). No route, service, model, JS behaviour or permission change. Do not touch .github/**, docs/lead/**, AGENTS.md or tests/artifacts/** (restore from base if a run rewrites them).

CONSTRAINTS
Only: app/templates/activity_contract_detail.html, app/templates/activity_evidence_row.html (only if needed), app/static/design/activity-report-detail.css, tests/test_activity_report_detail_design.py, docs/design/rollout/civ-140/**.

TESTS

Browser 1440 and 390: no horizontal page scroll; summary block ≤ 44rem; target marker x matches target/track ratio (±2 px); contrast ≥ 4.5:1 for all text. Full suite green.
